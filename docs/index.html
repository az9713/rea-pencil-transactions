Why you might use it

An automated design edit might rename the wrong object, move something into the wrong frame or overwrite a setting. A final picture alone does not explain which objects changed. You want a review step and a record you can undo later.

A concrete example. Select a supported frame, stage a new display name, then stage another supported change. Inspect the object list and rough previews before applying the group. If an object no longer matches the state the edit expected, the whole group is refused rather than partly applied.

1. Start with a design

Load the example or a supported .pen file. The initial design stays saved as the starting point.

2. Stage and review edits

Prepare supported rename, property or move operations. Compare their before-and-after values and rough diagrams.

3. Apply, undo or repeat

Apply the group together, save its history, and undo it later. Saved edits can be repeated only against matching starting design data.

What this page shows. The live workbench starts with an invented design. It runs independently of Pencil and does not resolve every component, font, image or layout rule.

Where it runs and what is still untested. This handles a limited part of the .pen 2.21 format. Its previews are simple outlines, not Pencil's finished rendering. Reopening the result in the real Pencil app has not been verified.

A TRANSACTION, NOT AN UNREVIEWED PATCH

Small vocabulary.
Strong refusal behavior.

01

Stage precisely

Rename a display name, set one supported property, or move/reorder an absolute-tree node. IDs are immutable. Each operation captures a target SHA-256; moves also guard the destination. A transaction guards the complete current document.

02

Commit atomically

All operations succeed or none become visible as committed state. Stale guards, ambiguous IDs, cycles, unsupported fields and unsafe tree moves fail without partial edits. The record retains object-level values, locations and child order before and after.

03

Replay durably

Native projects retain the original baseline, complete transaction history, redo future and cursor. Record and manifest hashes are checked on reload. Replay verifies every operation and differential, including inactive redo records.

Try a two-operation experiment.

  1. Open the workbench. The measured sample is selected.
  2. Stage a display-name change. The committed checkpoint stays unchanged.
  3. Choose Set → fill and stage a literal hex color. The after wireframe changes while the before view does not.
  4. Commit once. Inspect the object differential and transaction record hash.
  5. Undo, save the native project, reopen it, and redo. The tip checkpoint must be identical.
  6. Export the baseline and manifest. Reload that baseline, replay the manifest, and compare hashes. A different baseline is refused.

Pending staged operations are not committed or saved in durable exports. Commit or discard them first. Committing after undo replaces the redo branch only after an explicit choice.

What “exact” means here.

Hashes cover the UTF-8 encoding of this tool's canonical JSON: object keys sorted by JavaScript string order, arrays unchanged, finite IEEE-754 numbers. This is a documented local algorithm, not a claim of RFC8785 conformance. Whitespace, key order and numeric spelling are outside the value-preservation contract. Unknown document/node fields remain intact unless a supported field is explicitly changed.

Checkpoints detect a mismatch; they are not signatures or proof of authorship. Anyone able to replace a baseline and recompute the entire ledger can create a different valid history. The claim is deterministic, inspectable local replay, not adversarial authentication.

Respect the official engine.

The public format reference currently declares schema2.21 and is explicitly live. The official CLI already exposes engine-backed operations and rendering. Official guidance favors their app/CLI/MCP for production edits. This project uses an original JSON operation grammar over a restricted documented shape; it does not implement their MCP DSL, recover proprietary code or modify an installed Pencil application.

A source audit rejected third-party AI references naming older schema2.14 and older tool names as implementation authority. The official page URL, access date and downloaded-reference hash are recorded in sources.json. Fixtures are invented from the documented shape, not copied from a real design or presented as engine-validated outputs.

Read the wireframe limitations.

Only literal absolute geometry, simple hex fills, scalar radius and approximate text are drawn for frame/rectangle/ellipse/text. Unknown types, component refs, flex layout, themes, variables, scripts, images, gradients, effects and fonts remain in JSON but are not resolved. The application lists these omissions by JSON path. Scripts and external assets are never fetched or executed.

Supported operations and resource bounds

Rename sets name without changing IDs. Set permits x/y,width/height,fill,opacity,cornerRadius,content,fontSize with explicit type/range checks. Moves preserve local x/y; source/destination must be root or explicit layout:none frames. Component/opaque/flex subtrees are refused; no insert/delete, ID rewrite, ref rewrite, binding resolver or schema conversion exists.

Strict JSON only: duplicate/prototype keys, malformed Unicode, unsafe integers, nonfinite numbers, negative zero and comments are refused. Input5 MiB; compact baseline/current document1 MiB; JSON document depth30 and30,000 values;1500 tree nodes;30 transactions;20 operations per transaction; history2 MiB. Native envelope bounds are also enforced. Preview500 nodes,2,000 text characters/20 lines per node, clamped geometry. Native JSON values remain unchanged by preview bounds.

No automatic storage. Save the native project before closing. No real Pencil application, private file or installed directory was accessed; no official engine rendering or file-compatibility validation has been performed.

Verification is separated by authority.

Core tests cover atomic rollback, ID integrity, stale hashes, durable history, manifest tampering, unknown fields and fresh-process replay. Actual Chromium tests cover real downloads, native reimport, replay, hostile text and mobile layout. A packaged Windows renderer/isolation smoke is separate from those tests. None establishes compatibility with Pencil's proprietary engine.
